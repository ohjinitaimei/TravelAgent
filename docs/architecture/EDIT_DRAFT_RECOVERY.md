# 本机行程编辑草稿

日期：2026-10-20。Web 增加刷新、关闭后恢复编辑的能力，沿用同一个后端行程与调整接口；API Schema、业务算法和核心依赖没有变化。

## 使用方式

1. 打开已保存行程并编辑。发生改动后，页面提示草稿是否已写入本机。费用未知与 0、空白停留输入、分日、顺序、日期、预算和排序开关均可保留。
2. 刷新或重新打开同一浏览器、同一账号的空间，点击“恢复编辑草稿”。恢复过程不会提交规划或重算路线。
3. 恢复前按当前账号重新读取原行程，核对行程 ID、创建时间与可编辑基线；新增地点逐个重新调用 POI 详情，避免恢复操作自行耗尽后端工具并发槽位。任一请求失败或版本不一致时保留草稿，允许重试或显式放弃，不删除失败地点或生成替代数据。
4. 保存并重算后产生新的后端行程版本，清除对应草稿。未确认的提交先按原提交标识查询回执；已完成的调整不会再次作为草稿恢复。明确拒绝、失败或取消保留草稿。

每个账号在当前浏览器保留一份草稿，保存期限为最后一次编辑后的 7 天，JSON 字符串长度不超过 32,768；过期或格式错误的内容不能恢复，需显式放弃。存在草稿时先恢复或放弃，才允许开始另一份编辑。主动放弃、主动退出登录会清除该账号草稿；会话失效则保留，重新登录原账号可恢复，其他账号没有恢复入口。

## 存储与数据流

```text
编辑输入 → editSnapshot → 白名单/大小检查 → 按账号命名的 localStorage
重新打开 → 提交回执与任务同步 → 用户点击恢复
         → GET 原行程 → ID/时间/可编辑基线核对
         → GET 新增地点详情 → 原编辑器与地点预览
保存 → 既有异步 adjust → 后端真实路线与调度 → 新版本 → 清除对应草稿
```

`apps/web/src/editDraft.ts` 只存用户输入、地点 ID、原行程标识与基线、选定日期索引及更新时间；不缓存地点名称、坐标、评论、价格或交通事实，也不存凭证。恢复的原地点来自合法保存记录，新增地点来自当前真实 Provider/MCP 详情接口。恢复成功后仍需用户保存，交通成本由后端重新查询和计算。

写入和删除前比较上次读到的存储值，配合 storage 事件识别另一页面的更改；恢复等待网络时还会核对最初的存储实例与快照，防止旧恢复覆盖期间产生的新草稿。发生冲突时阻止当前页面覆盖、删除或提交，提示刷新后恢复最新草稿。这是浏览器本地的冲突保护，localStorage 不提供跨标签页事务，不作为多人实时协作机制。多个页面完全同时写入仍存在竞争窗口。

本机配额不足或浏览器禁止存储时明确提示保存失败；编辑与后端保存仍可用。原生离开提示保留，但其显示由浏览器决定。本机草稿不会跨设备同步，也不能保证浏览器清理存储、隐私窗口关闭或磁盘故障后的恢复。localStorage 按账号分键属于页面恢复隔离，不是加密存储或针对同机其他人员的保密措施。

## 验收

新增 TypeScript 检查覆盖字段白名单、未知/零值/未完成输入、有效期与格式、原版本核对、账号隔离、旧页面冲突、配额失败与显式清理。浏览器场景覆盖刷新恢复与保存清理、原版本变化/404、详情失败保留与重试、多页面冲突、已受理调整丢失响应后的恢复、存储失败后直接保存，以及会话失效后的原账号恢复和主动退出清理。

运行方式沿用 [ACCEPTANCE.md](../ACCEPTANCE.md)。页面故障注入仅在 tests 中定义，隔离临时库、禁用真实凭证；不把测试 POI 当作真实高德验收结果。本轮未新增真实高德请求或修改个人行程库。
