## 用户操作

Web 创建表单及行程编辑增加“单段交通上限（分钟）”“每日交通上限（分钟）”，均可不填。它们是用户指定的硬约束，适用于当前所选步行或驾车模式，并包含真实站间、所选出发和返回交通。切换交通模式后仍使用所填上限，系统不自动切换模式或放宽条件。留空仅展示负担，不替用户规定统一的体力阈值。

保存结果增加“路途负担”：逐日停留分钟、交通分钟、最长一段、交通占已排时间比例，以及交通不少于停留时的复核提示。分母是停留和已选交通之和，不是整天可用时段。无实际路段时最长一段为 null；不制造零分钟路段。报告来自后端已查询路线，读取和切日不额外调用地图接口。

超限时显示失败任务原方案的逐日诊断及超出分钟。按钮只定位当前输入，不自动修改或提交。扩大每日时段、缩短停留不等于降低交通时长；可以自行修改地点、交通方式或上限后创建新任务。编辑失败保留原版本和本机输入，刷新后可恢复草稿，显式留空清除上限，版本对照区分数值与“未设置”。

未选择一侧的往返、站内步行、排队、餐饮等待及未来路况不计入；没有提示也不等于主观满意度或体力适合性通过。自然语言 Agent 本轮不推断这些数值；应用新需求草案会按新表单重置可选上限，需要重新核对。

## API 契约与流程

| 字段/对象 | 行为 |
| --- | --- |
| `PlanRequest.max_leg_travel_minutes` | 可空严格整数 1–1439，每个实际路段的上限；相等通过 |
| `PlanRequest.max_daily_travel_minutes` | 可空严格整数 1–1439，每日已选交通总和上限；相等通过 |
| `EditRequest` 同名字段 | 省略保留来源值，显式 null 清除；0、浮点、布尔和数字字符串拒绝 |
| `Itinerary.travel_load` | 新规划保存逐日事实汇总、模式和所设上限；旧记录默认 null，读取时不制造报告 |
| `Error.travel_constraints` | 兼容性新增可空 `TravelConstraintDiagnostics`，含操作、来源版本、原分日基准、模式、原上限、超限日期及有向路段 ID/超出分钟 |
| `travel_constraint_exceeded` | 已查询原方案/有限候选未满足上限，失败任务不保存半成品，不允许原条件自动重试 |

Web → 共享生成类型/客户端 → FastAPI 异步任务 → 统一 Provider/MCP 真实 POI/路线 → 既有排序/调度 → 后端 `travel_load.py` 汇总及限制检查 → 保存结果或持久化失败事件/诊断 → SSE/轮询。前端只显示报告与格式化百分比，不计算或替换交通事实。

现有有限地理候选同时受每日时段与所设交通限制约束；`PlanningMetrics.feasible` 现在表示两类检查均通过。如果原方案违反上限而已查询候选满足全部约束，可采用候选；原方案可行时保留原有交通、距离和最忙一天不恶化的接受规则。继续保持默认 64 次工具预算和任务时限，不增加召回搜索或交通 API 调用，不保证全局最优或穷尽所有可行顺序。

如果时间与交通上限同时违反，优先返回既有时间诊断；修正后仍会核验交通上限。失败诊断是原方案事实，不随当前输入变化，也不冒充可行候选。用户明确调整后才提交新任务。

老请求的空新增字段从任务幂等指纹中规范化去除，保留旧提交收据；非空新上限不同仍冲突。旧行程、错误、编辑草稿缺省值保持兼容，原有账号和来源隔离沿用。OpenAPI 与 TypeScript 类型重新生成。

本轮两次有界运行均使用生产 API/Web、用户已有合法授权和临时数据库，没有 FixtureProvider、模拟结果、模型或真实 JS SDK。外部调用后没有自动重试。

1. 南京、2026-10-23 起、两天两站、步行、每站 30 分钟、09:00–22:00、南京站出发/南京南站返回，单段及每日上限均为 1439。旧验证脚本在任务仍运行时触发 30 秒等待门槛并结束服务，没有观察到终态，不记作规划通过或规划算法失败。实际只进入首次规划，消耗上界 23+2 次辅助搜索，即 25。证据在 `artifacts/travel-load-live/2026-10-22/`。
2. 缩为单日两站，在原定总预算内预留上界 46。验证脚本改为按既有后端任务期限观察终态，产品时限不变。真实原规划成功、报告展示、单段上限改为 158 后返程 159 分钟超出 1 分钟的失败、诊断显示与刷新恢复草稿均通过。截图中的原方案停留 60、交通 224、最长一段 159、占比 78.9%。随后显式清除单段上限再保存时，任务被高德拒绝（10021），原版本与草稿仍在。该运行整体失败，没有声称新版本保存成功；后续真实 MCP 阶段未执行。证据在 `artifacts/travel-load-live/2026-10-22-single-day/`。

第二次最终异常捕获只保存总失败、截图和 HTTP 日志，没有保留完整的中间成功响应；上述部分通过范围以脚本已执行的断言及人工检查 `load.png`、`constraint.png`、`failure.png` 为证据，不伪造原始 API 报告。两次累计结构性上界 71，未超过事先声明的 84，不是实际账单计数。后续没有追加付费运行。

高德 Web 服务官方错误码将 `10021` 定义为账号某服务接口的 QPS 超限，参见 [官方错误码](https://lbs.amap.com/api/webservice/guide/tools/info)。不能据此推断 Key 被删除、日总额度耗尽或整个授权失效。本轮保持明确失败，没有填入替代 POI、交通或价格。真实 MCP 的本轮复验和清除后真实保存仍须在可用配额下重验；隔离 stdio MCP 与浏览器流程单列，不混称真实高德全链路通过。
