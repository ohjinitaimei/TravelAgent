# 弱网恢复与最大行程验收

日期：2026-10-20。环境：Windows、Python 3.12、锁定依赖，Chromium / Firefox / WebKit Headless，1440 × 1000 视口。此阶段在本地开发和验收，没有上传 GitHub。

## 用户可见行为

规划、编辑重算与需求整理继续使用既有异步任务、提交回执和同一后端。状态读取失败时，共享客户端最多连续尝试 5 次，重试前分别等待 250 / 500 / 1000 / 2000 ms；运行中成功读完状态与事件后清零。已终结任务的事件读取暂时失败不会阻止读取保存结果。单次请求期限为 15 秒，整轮状态等待期限为 210 秒。达到期限或重试上限会提示恢复连接，不会重新创建规划。

本轮修复任务完成与结果读取之间的缺口：任务已经成功，但读取行程或需求草案失败时，页面显示“任务已完成，结果尚未同步”。原行程和编辑内容保留，旧版本提示保持可见，开始规划与保存重算暂时禁用。网络恢复事件或“恢复连接”继续查询同一任务与保存结果；编辑中的完成结果也能同步。结果赋值成功后解除等待，保存列表刷新失败单独报错，不将已展示的结果误标成未同步。

该状态属于当前页面的恢复状态；刷新仍使用已持久化的任务 ID 重新查询终态与结果，无需持久化行程事实到本机编辑草稿。取消仍终结当前等待并中止轮询，迟到的旧状态不能重新激活已取消任务。

## 自动场景

`tests/browser/resilience.spec.ts` 是独立套件，每个引擎使用独立临时数据库、端口和生产构建目录。单 worker、无自动重试，5 个场景：

1. 关闭 SSE，状态读取增加 250 ms 延迟并间歇失败，事件读取首次失败；轮询恢复后事件条数与后端记录一致，只创建一个带提交标识的任务。
2. 连续 5 次状态读取失败，额外观察 700 ms 确认重试已停止；恢复连接后使用原任务 ID，只有一次创建 POST。
3. 已保存行程编辑费用后，后端任务成功但结果读取失败；明确提示待同步、保留原版本并禁用重复保存。联网后读取子版本，用户费用保留，原版本仍可读取且不变，只有一次调整 POST。
4. 截获状态快照并延迟 2200 ms，等待期间取消；迟到响应到达后页面和后端仍为已取消，没有生成行程，也没有第二次创建 POST。
5. 3 天 × 4 站的最大行程：12 个不同地点、9 段路线，每段 512 个测试坐标点，共 4608 点；轮流切换日期、编辑每一天的费用、保存新版本、刷新重读。验证原版本不变、12 站保留、费用保留、路线查询不超过现有 48 次上限，本机草稿小于 32768 字符且不含路线与坐标事实。

最大响应由 `tests/maximum_fixture.py` 显式构造，复用原规划算法，数据仅存在于标记 TEST ONLY 的测试服务。它不是真实交通、授权数据质量样本或生产 Provider 的降级路径。

## 性能方法与门槛

`scripts/browser_test_web.mjs` 在 `resilience` 套件下使用 Vite 生产构建及 preview 代理；构建目录必须位于本次隔离的 `.tmp/` 内。常规本地和账号功能套件保留 Vite 开发服务器。测试清空地图与模型凭证并阻止页面外部 HTTPS，避免开发热更新和外部 SDK 网络影响页面测量。

每个操作从浏览器时间戳开始，经过 Playwright 操作、必要的页面断言，再等待两次 `requestAnimationFrame`。使用 `performance.timeOrigin + performance.now()`，保证刷新前后时钟可比较，并拒绝负耗时。该数据包含测试驱动开销，是本机回归指标，不是纯 Vue 渲染时间或面向所有设备的服务承诺。

日期切换 12 个样本、费用输入 3 个样本合并取最近秩 P95；15 个样本的 P95 等于本轮最大值，不宜解释为大样本统计分布。门槛为 P95 小于 1500 ms、最大值小于 3000 ms、刷新并显示结果小于 8000 ms。重复切换后 DOM 元素数保持不变，刷新后总元素数少于 3000。打开编辑器另外记录耗时。

最终三引擎 9 份报告已逐一核对：每引擎 local 27、auth 10、resilience 5，共 126 次页面执行，无失败、跳过或重试后通过。加上 Python 92、共享客户端 23，共 157 个逻辑用例、241 次执行；类型检查、生产构建和 API 契约生成一致性通过。

| 引擎 | 切换/输入 P95（ms） | 打开编辑器（ms） | 刷新并显示结果（ms） | 响应对象序列化（字节） |
| --- | ---: | ---: | ---: | ---: |
| Chromium | 95.7 | 91.0 | 327.2 | 226550 |
| Firefox | 133.0 | 127.0 | 711.0 | 226550 |
| WebKit | 281.0 | 227.0 | 534.0 | 226550 |

三引擎均满足上述门槛，重复切换未增加 DOM 元素数。响应约 221 KiB，包含 12 站和 4608 个路线点。每次完整运行会更新本机报告；这些计时数据不是生产业务记录，也没有证明真实高德 SDK 或低性能设备具有相同表现。

## 复现与结果文件

按根 README 安装锁定依赖及浏览器后，在仓库根执行：

```powershell
# 只运行新增的生产构建套件，共 5 × 3 个场景
.\.venv\Scripts\python.exe scripts/verify_browser.py --suite resilience
# 完整运行每引擎的 local / auth / resilience 三套验收
.\.venv\Scripts\python.exe scripts/verify_browser.py
```

`--browser chromium|firefox|webkit` 和 `--grep` 可用于定向排查。最终验收须去掉 `--grep`。报告在 `artifacts/browser-reports/{engine}/resilience.json`，其中最大行程用例附有 `performance.json`，包含各次操作耗时、响应对象重新序列化后的 UTF-8 字节数（非压缩流量）、浏览器与数据规模。失败 trace/截图和服务日志沿用其他套件的目录，全部被 Git 排除。CI 使用默认完整入口，包含这套验收；此阶段未运行云端 CI。

## 验证边界与后续

此阶段覆盖确定性的读取延迟、连续断线、恢复及最大行程页面读写，不模拟特定运营商带宽、随机丢包或长时间压力。没有新增真实高德、模型或 MCP 远程调用；真实地图 SDK 的渲染和瓦片网络耗时不在此性能结论中。已有真实数据验收见 [LIVE_AMAP.md](LIVE_AMAP.md) 和 [BROWSER_ACCEPTANCE.md](BROWSER_ACCEPTANCE.md)。

后续优先补正式环境的 HTTPS、域名授权、配额与备份恢复验收，再扩大真实城市与交通模式样本；NVDA/VoiceOver 人工朗读、Safari 真机和移动端同后端联调单独安排。保持既有 Provider、推荐、优化和调度层，不增加前端 Agent 或模拟业务降级。
