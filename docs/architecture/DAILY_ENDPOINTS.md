# 逐日独立起终点

日期：2026-10-22。支持 1–3 天按日期分别选择出发地、住宿点或返回地，沿用统一 FastAPI、AmapProvider/MCP、既有推荐、最近邻排序、有限分日候选和调度。没有新增 Agent、核心依赖或业务数据库迁移；仅在本地开发与验收。

## 契约与兼容

`PlanRequest.day_endpoints` 为可空数组，按 `start_date` 起的日期顺序排列。非空时长度必须等于 `days`，每项仅包含可空的 `origin_poi_id` 和 `destination_poi_id`，ID 必须来自真实搜索、用户合法输入或已有业务记录，并能由当前真实 Provider 核验。空侧表示不包含该侧往返，不根据日期或地名猜测住宿。

- `day_endpoints` 缺省或 `null`：使用原有 `day_origin_poi_id`、`day_destination_poi_id`，所有日期共用。
- 数组模式：共享字段须为空；每项独立，不继承昨日返回地，也不回退共享字段。`{}` 表示当天两侧均未设置。
- 空数组、长度不符、空白 ID、非字符串 ID、多余业务字段，以及同时设置逐日与非空共享 ID，均拒绝。
- `EditRequest` 省略数组保留来源设置；提供数组整体替换逐日选择，单侧 `null` 只清除该日期。提供 `day_endpoints:null` 切回共享模式，并按显式提交的共享字段处理。
- 编辑仍保留原天数；新增创建可调整天数。新字段空值从任务幂等指纹中去除，旧收据不重复创建任务；不同日期顺序仍是不同请求。

`Day` 继续保存当天实际 POI、入站/返程 Segment、离开和返回时间；地图、时间轴和负担报告直接读取这些事实。旧行程和旧错误无需重写。OpenAPI 与生成 TypeScript 同步更新，后续 App 可使用相同数组和任务轮询接口。

## 调度与调用预算

`backend/travel/endpoints.py` 统一解析共享/逐日设置。请求内按 ID 复用详情，有向路线按 `(origin_id,destination_id)` 复用；同一相邻 POI 不生成虚构的零分钟路段。每天从当天出发地计时，末站至当天返回地计入结束时限、交通上限和预算缺项。费用缺失仍未知。

没有自动安排跨夜接驳，也不默认次日从前一天返回地出发。选择不同地点时，用户须自行确认跨夜安排；酒店价格、营业状态、房态与预订结果没有新增授权来源，不生成替代结果。

64 次工具上限保持不变。预检计算唯一详情上界、各天边界与原方案站间路线。不同日期的边界会让跨日候选产生新路段，因此在任何候选查询前，还计算原方案与已接受候选的全部有向路线并集；无法在剩余额度内核验的候选直接裁剪，继续保留原算法及选择规则。比较结果标记 `candidate_search_limited`，不把未查询候选写成已验证结果。

测试中的三天三站、六个不同边界案例：原方案加一个整日轮换候选需 61 次调用，第二个候选会超预算并被裁剪；实际路线 54 条，无重复查询。三天十二站且六个独立边界的原方案保守上界 67，在任何外部调用前拒绝；相同规模的保留顺序编辑上界 33。可减少站点、明确取消一侧或保留顺序，不自动改变用户要求。共享起终点的既有 63 次实测与 64 次预留上限保持。

## Web 操作与本机恢复

勾选“按天设置出发和返回”时，把当前共享选择复制到各日，再由用户逐日修改。切回共用时，明确使用第 1 天选择；增加天数的新日期留空，减少天数只保留对应日期的设置。切换说明直接展示在控件中。

编辑的地图地点预览按当前日期显示起终点；路线和时间仍等保存后重算。差异与来源版本对照显示“第 N 天出发地/返回地”和保存的名称，单日清除不改变其他日期。失败、离线与未确认提交沿用原恢复流程，不自动重放任务。

工作区与编辑草稿只保存逐日 ID 和用户输入，不写入 POI 事实、价格或折线。旧 v1 草稿缺字段规范化为 `null`；新草稿验证数组长度、模式互斥和字段白名单，拒绝嵌入 Provider 数据。恢复来源版本后，新增 ID 仍需真实详情校验；没有结果时保留草稿并报错。
