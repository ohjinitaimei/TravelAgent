# 已保存行程版本浏览与对照

更新日期：2026-10-21。本阶段仅本地开发与验收，未上传 GitHub。

## 操作与数据边界

“已保存行程”提供标题、城市、出发日期或版本 ID 搜索，原行程/调整版本筛选，以及保存时间/出发日期排序。每张卡片显示版本标识、保存时间、实际来源和列表内直接调整数量；工作台同时显示当前版本身份，并可打开来源或浏览版本。

关系只取 `Itinerary.parent_id`。相同标题和日期不表示同一条版本链；“直接调整版本”不包含孙版本，不假造连续版本号。当前列表来自既有接口最近 50 项，筛选和关系计数仅针对已载入内容，页面明确范围。来源超出列表时仍可按 ID 单独读取；未实现全库分页、任意两版比较、删除、合并或回滚。

点击“对比来源版本”依次重新读取调整版本及其直接来源，最多两个既有 `GET /api/v1/travel/itineraries/{id}`。校验返回的 ID 和父子关系后才显示结果，不将缓存列表当作授权依据。来源缺失、越权或网络失败均不显示残留表格，并允许显式重试。关闭或离开页面后，迟到响应不能重新打开或覆盖对照。

对照展示已保存的站数、停留、站间道路时间/距离、费用小计、站点费用缺项和完整预算。沿用编辑差异模块展示地点顺序、分日、单站停留、用户费用与已保存条件变化；不重写业务算法。缺失/不匹配的站间路线显示“交通数据不完整”，缺失保存时间显示“保存时间未提供”，缺失总额显示“未知”。0 元只表示用户明确录入，不代表其他缺失费用免费；道路事实取各版保存时结果，不代表相同时刻或未来出行时刻。

筛选和对照只保留在当前组件内，不写浏览器持久存储，不清理编辑草稿，不调用 Provider、LLM 或路线优化。打开来源或调整版本复用现有打开流程；有未保存修改时先显示原有放弃确认。对照标题可聚焦，关闭后返回触发按钮；来源读取期间关闭也等待按钮重新启用后恢复焦点。

## 可复现验收

先按根 README 安装依赖和浏览器，再运行：

```powershell
python scripts/verify_repository.py
python scripts/verify_browser.py
# 定向场景，须分开指定套件；resilience 没有此名称的用例
python scripts/verify_browser.py --browser chromium --suite local --grep "saved versions"
python scripts/verify_browser.py --browser chromium --suite auth --grep "saved versions"
```

五项逻辑检查覆盖真实父边关系、排序缺省与不变性、未知/0 元、路线不完整和来源错配。四项工作台场景覆盖直接子版本与孙版本、空筛选/窄屏、只读与草稿保护、来源未载入/404/重试，以及关闭后的迟到响应。账号场景使用明确 TEST ONLY 元数据篡改，来源请求仍走真实鉴权并返回 404，不显示其他用户记录。所有测试数据仅在隔离测试服务内。

首轮定向测试发现：读取过程中关闭对照时，触发按钮仍被 DOM 禁用，立即调用 `focus()` 无效。修复为等待 Vue 更新再恢复焦点，保持迟到响应代次校验；未放宽测试超时或启用重试。另一次定向编排未指定套件，前两个套件通过后因 resilience 无同名场景退出；完整矩阵按各套件正常执行，不把无场景当作测试通过。
