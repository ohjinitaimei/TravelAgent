# Web 完整用户流程与使用说明验收

日期：2026-10-22。沿用 Vue3 Web、共享客户端与同一 FastAPI 服务，本轮仅新增说明和连续验收场景，没有修改业务运行代码、API 契约、数据库结构或依赖。仅本地开发与打包，没有上传 GitHub。

用户操作入口：[使用手册](../USER_GUIDE.md)。安装、配置、界面动作、恢复方式和能力边界已逐项核对源码；根 README 与文档索引提供入口。修正了旧说明中“尚须实现鉴权”和固定仓库可见性的表述。

## 连续操作与数据流

| 用户动作 | 实际后端/存储 | 验收要点 |
| --- | --- | --- |
| 填表、显式开始规划 | `POST /tasks` → 有界任务进程 → Provider/Tools → 既有推荐、路线与调度 → SQLite | 请求返回任务，状态/事件异步读取；不让模型计算交通 |
| 时段不可行、按诊断修正再提交 | `GET /tasks/{id}` 中持久化的错误与分日诊断；显式创建新任务 | 失败任务无行程，旧错误保留；定位表单不自动提交 |
| 成功后查看预算 | `GET /itineraries/{id}` 的保存事实 | 缺失费用不补值，预算总额保持未知 |
| 编辑并刷新 | 当前账号的本机输入草稿；恢复前读取原行程 | 草稿不保存 Provider 事实，恢复不自动 POST |
| 断网保存、恢复上次提交 | 同一 `Idempotency-Key` 与 `/submissions/{key}` 提交收据，再受理 `/itineraries/{id}/adjust` | 两次调整发送尝试只受理一次；新版本关联原版本 |
| 搜索、对照、重开原版本 | `GET /itineraries?query=...`、两个版本的 GET | 只读浏览不触发规划/调整；原版本和旧失败记录不变 |

前端事件可走 SSE `/tasks/{id}/events/stream`，不可用时使用状态/事件轮询。移动端未来复用相同任务和 Schema，通过轮询接入；本轮没有 App 真机联调。

主要实现对应 `apps/web/src/App.vue`、`components/SavedTrips.vue`、`VersionComparison.vue`、`TimeConstraintGuide.vue`、`editDraft.ts`，以及 `packages/api-schema/client.ts`、`backend/travel/api.py`、`tasks.py`、`planner.py`、`provider.py`、`store.py`。本轮新增 `tests/browser/resilience.spec.ts` 中的 `complete user journey` 连续场景，复用既有隔离服务，不添加生产模拟入口。

## 生产构建自动验收

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.cache/playwright"
.\.venv\Scripts\python.exe scripts/verify_browser.py --suite resilience
```

新增场景在一个浏览器上下文中连续执行：

1. TEST ONLY 城市、1 天 2 站、出发日 2026-10-23、预算 300，结束时间 09:01；等待失败诊断，确认无行程且不可按原条件重试。
2. 从诊断定位每日结束时间，改为 18:00，显式提交新任务；等待新任务 ID 与成功提示，读取两站行程与事件。
3. 预算页面确认完整总额未知，返回编辑，将首站停留改为 90 分钟、费用录为 0，等待本机保存提示。
4. 刷新并显式恢复草稿，确认改动仍在且未自动发送调整请求。
5. 浏览器离线后保存；联网后“恢复上次提交”，两次发送沿用相同非空提交标识，后端只产生一个调整版本。
6. 通过完整 ID 搜索，查看来源对照，重开原版本并刷新；核对原行程及失败错误不变，浏览不增加写请求。

报告为 `artifacts/browser-reports/{chromium|firefox|webkit}/resilience.json`，新增场景附带 `complete-journey-test-only` 的 ID/计数摘要。所有自动验收业务事实来自 tests 中明确标注的 TEST ONLY Provider，不访问高德、模型、SDK或用户数据库。

本阶段该套件为每引擎 6 项：连续流程 1、既有弱网/取消/最大行程 5，三引擎共 18 次。首次 Chromium 定向运行因测试将含 `¥` 的预算标签误写为完全匹配而超时，发生在提交前；核对页面与源码后改为标签包含匹配，定向重跑通过。未修改产品标签、超时、断言或自动重试设置。首次失败的 trace/截图为本机 artifacts，不计作通过。

全检查集现为 Python 146、TypeScript 30、页面 62 个场景 × 3 引擎 = 186，即 **238 个逻辑用例 / 362 次执行**。这是检查集规模。本轮实际重跑生产套件 18 次、定向复查和类型/构建/Schema；Python 146、TypeScript 30、工作台 43 × 3 与账号 13 × 3 的通过记录来自 2026-10-21 的未变业务代码基线，不能表述为本轮重跑全部 362 次。基线的系统休眠和恢复后复跑另记在 [ACCEPTANCE.md](../ACCEPTANCE.md) 与 [分页恢复记录](SAVED_PAGE_RECOVERY.md)。

## 授权真实数据流程

同日另用生产 FastAPI、生产 Web 构建、独立临时 SQLite 和用户已有授权的高德 Web 服务 Key，在 Chromium 执行同一路径。传输为 `direct`，使用真实 Provider，没有替换业务结果：

| 项目 | 实测结果 |
| --- | --- |
| 输入 | 南京、公园、2026-10-23、1 天 2 站、步行、停留 30 分钟、预算 300 |
| 初始时段 | 09:00–09:01；需要 81 分钟（停留 60 + 站间交通 21），超出 80，返回 `time_constraint_exceeded` |
| 修正 | 每日结束改为 18:00，显式创建成功的新任务 |
| 草稿恢复与调整 | 首站 30 → 45 分钟，费用未知 → 用户录入 0；刷新恢复和离线提交恢复通过 |
| 保存语义 | 4 次发送尝试，3 个受理任务（失败规划、成功规划、调整），只有 1 个直接调整版本 |
| 版本与预算 | 对照、搜索、重开和刷新通过；来源版本与旧失败记录不变，总预算仍未知 |
| 来源检查 | 每站 POI 为 `amap` 且有获取时间；站间路线来源为 `amap` 且有道路折线 |
| 只读浏览 | 无新增规划/调整 POST |
| 隔离 | 临时库，服务优雅退出；不改用户数据和私密配置 |

本机报告 `artifacts/user-journey-live/2026-10-22/report.json`，截图 `comparison.png`；运行脚本在忽略的 `.tmp/live-user-journey.py` 和 `.mjs`，不随源码分发。克隆者可按使用手册与本表输入显式复验；地点和交通可能随真实 API 改变，不要求复现固定名称或 21 分钟。

此次按两次规划各最多 1 搜索 + 2 路线、一次调整最多 2 详情 + 2 路线控制调用，上限 **10 次**。这不是外部账单实测计数；服务日志不记录带 Key 的 URL。离线失败的调整未被后端受理，只读浏览不再调用 Provider。

本轮没有加载真实地图 JS SDK、调用模型或 MCP，没有重跑 HTTPS、恢复演练、NVDA/VoiceOver 人工听读或移动真机。此前 SDK、模型、MCP 和 HTTPS 的结果保留原日期及范围。本次单个真实样本证明流程可贯通，不代表推荐满意度、未来营业/预约状态、票价库存或公网部署通过。
