# 多日概览与真实数据质量验收

日期：2026-10-20。本轮在本地完成 Web 增量和南京、苏州的授权高德样本；未上传 GitHub，未改动个人业务库。

## 页面行为

行程上方并排展示各天日期、站数、用户设定停留时间、已保存站间交通分钟/公里、用户已录入站点费用和未填站数。点击日期切换原有地图与时间轴，支持 Tab、Enter、Space，以及方向键、Home、End；当前日期有可见样式和 `aria-pressed`。

概览只汇总后端返回的已保存事实，不在前端计算新路线或调度。站点费用与完整预算分开：未填费用保持未知，明确录入 0 元才记为已填，交通、住宿等缺项不计作免费。

编辑期间，各天只显示修改后的站数，并将日期标为原日期；路线、时间与费用提示待保存核算，避免将旧路线误当成编辑结果。跨日移动后概览立即更新站数，保存仍使用原有后端异步重算、新版本与原版本保留机制。窄屏改为单列。

新增 `DayOverview.vue`，接入已有 `Itinerary` 生成类型。没有增加 API、Schema、业务算法或依赖；地图实例生命周期及代理保持原实现。

移除全局 CSS 的 Google Fonts 远程 `@import`，保留原字体栈与系统回退，工作台加载不再依赖外部字体服务。浏览器测试的 HTTPS 拦截覆盖整个 context，包括新标签页。

## 可复现真实样本

先配置自己的合法 `backend/.env` 高德 Web 服务授权，并安装根 README 中后端与可选 MCP 依赖，再运行：

```powershell
.\.venv\Scripts\python.exe scripts/verify_live_quality.py --live-amap --date 2026-10-21 --output artifacts/live-quality/report.json
```

脚本显式要求 `--live-amap`，会消耗真实接口配额。固定四个任务：南京步行、苏州驾车各走一次直接 Provider 与 MCP。均为“公园”、2 天、每天 2 站、每站停留 30 分钟、每日 09:00–22:00；日期与时段是验收输入。最多 4 次搜索、48 次有向路线查询，不自动重试业务失败，不调用模型。

脚本在 `.tmp/` 创建独立库，以回环地址启动实际生产 API，经创建任务、查询状态、读取行程/事件验证链路。没有替换 Provider 或开启测试数据；退出时取消遗留任务、关闭服务并清理临时库。精简报告只写入被 Git 忽略的 `artifacts/`，不输出 Key、原始供应商响应或带凭证 URL。

真实脚本固定使用高德官方 `https://restapi.amap.com`，不沿用本机自定义 Provider 地址。

验收门槛包括：共享 Pydantic Schema、请求一致、连续日期、唯一 POI、真实来源与获取时间、缺失字段标记、路线起终点/模式/几何、停留与站间时间衔接、每日结束时间、优化对比与实际路线一致、预算未知项、调用上限，以及 MCP 实际连接事件。离线 `test_live_quality.py` 用明确 TEST ONLY 输入验证拒绝错误来源、日期、时刻、路线关联和虚构零费用；这些离线输入不进入真实脚本或生产服务。

## 本次结果

四项全部通过，实际合计 20 次高德 Web 服务请求：4 次搜索、16 次路线查询；两个隔离 API 均优雅退出。

| 城市与方式 | 每天站间距离 | 每天站间分钟 | 合计 | 直接 / MCP 任务耗时 |
| --- | --- | --- | --- | --- |
| 南京 · 步行 | 1.552 / 3.886 km | 21 / 52 | 5.438 km、73 分钟 | 4.86 / 8.11 秒 |
| 苏州 · 驾车 | 3.659 / 2.928 km | 12 / 14 | 6.587 km、26 分钟 | 5.06 / 7.08 秒 |

两种传输本次的 POI、距离、分钟和缺失字段结果一致；两组均为 `no_geographic_change`，未采用新的跨日分组。该结果不能证明全局最优或新的算法收益。

南京 4 个地点均缺人均消费、3 个缺营业时间；苏州 4 个均缺人均消费。本次不录入站点费用，每份行程保留 7 个预算缺项，`budget.total=null`。营业字段有返回也不表示已验证出行日开门；人均消费不能代替门票，真实预约、票价、库存、完整交通成本和未来时刻交通仍需对应授权数据。

报告保存于本机 `artifacts/live-quality/2026-10-20/report.json`，不随 Git 或发布包交付。外部数据和实时路况会变化，重新运行可能产生不同结果或明确失败；不以模拟数据补齐。

页面验收新增三项：概览与实际 API 事实一致、键盘切日及窄屏无横向溢出；跨日移动更新预览站数、隐藏旧交通/费用、保存后核对新事实和原版本，以及 0 元和未填区分；工作台与第二个标签页完成加载且不请求远程样式或字体。完整三引擎与其他检查的结果以 [ACCEPTANCE.md](../ACCEPTANCE.md) 为准。截图只使用 TEST ONLY 页面数据；本轮没有重新加载真实 JS SDK，真实底图和代理的既有记录见 [AMAP_PROXY.md](AMAP_PROXY.md)。
