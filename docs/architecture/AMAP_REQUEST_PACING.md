# 高德共享请求节流与限流恢复

日期：2026-10-22。Web、API 直接查询、异步任务和随仓库启动的 MCP 仍使用同一个 AmapProvider 与既有路线算法；不新增 Agent、业务数据缓存或依赖。

## 请求路径与状态

```text
Web / 后续 App → FastAPI → TravelTools → AmapProvider → ProviderGate → 授权高德接口
                     └→ 任务进程 / 本机 stdio MCP ──────────┘
                                       共享 amap-rate.sqlite3
```

此前按用户/全局的业务准入配额继续生效。本轮新增安装级外部请求节奏：所有 POI 搜索、详情与步行/驾车请求先取得 SQLite 原子准入，再调用真实接口。数据库只存下一次允许准入的时间和冷却截止时间；不存 Key、账号、POI、路线或价格。

等待和 HTTP 调用期间不持有数据库锁。等待有上限；进程退出不会给整个行程预订后续时隙。不保证公平排队，拥挤时返回明确错误。已经准入或正在执行的 HTTP 不因另一个请求进入冷却而自动取消。保留现有任务取消、超时和 MCP 总预算，工具调用次数上限不变。

| 配置 | 默认 | 允许范围 / 作用 |
| --- | ---: | --- |
| `TRAVEL_AMAP_MIN_INTERVAL_SECONDS` | 1 | 0.05–5，安装内两次准入的最小间隔 |
| `TRAVEL_AMAP_MAX_WAIT_SECONDS` | 3 | 0.1–5，单次准入等待预算 |
| `TRAVEL_AMAP_COOLDOWN_SECONDS` | 5 | 1–60，收到 QPS 拒绝后的共享冷却 |
| `TRAVEL_AMAP_RATE_DB_PATH` | 业务库同目录的 `amap-rate.sqlite3` | 可选独立文件；各进程须指向同一位置 |

配置见 `backend/.env.example` 和 `deploy/backend.env.example`。默认间隔不代表账号购买的 QPS；同一账号在其他程序产生的调用、日配额和供应商策略仍可能导致拒绝。此方案用于现有单 API 安装及其本机子进程，不提供多主机配额协调。

打包启动的 MCP 自动继承解析后的绝对节流路径和四项白名单配置，不继承业务库路径、用户会话、模型或 GitHub 凭证。独立手动启动 MCP 时，如 API 使用了自定义数据目录，须显式配置相同 `TRAVEL_AMAP_RATE_DB_PATH`。该文件与业务 SQLite 分开，不能指向业务库本身。

节流文件放在服务账号可写的数据目录，不能在 Web 静态目录。部署预检校验独立绝对路径、父目录和数值边界，不创建文件。它不是业务备份；现有备份命令只备份业务库。运行期间不要删除节流文件来绕过冷却；恢复业务数据不会恢复供应商的实际配额。

## API 契约与恢复

统一 `Error` 新增可空的严格整数 `retry_after`（1–300 秒）。直接 REST 失败还提供 `Retry-After` 响应头；异步任务把建议写入 `Task.error`，由 Web SSE/轮询和后续 App 轮询读取。旧错误缺省为 `null`，OpenAPI 和 TypeScript 已同步生成。

| 错误码 | HTTP | 含义 |
| --- | ---: | --- |
| `provider_busy` | 429 | 本地有界等待无法取得准入 |
| `provider_rate_limited` | 429 | 上游 QPS 拒绝或共享冷却尚未结束 |
| `provider_gate_unavailable` | 503 | 本地调度状态无法安全读写，停止外部调用 |
| `invalid_provider_gate_config` | 503 | 配置无效，需修正服务端配置 |

高德 `10014/10015/10019/10020/10021` 按 QPS 错误进入冷却；`10044` 日配额、授权错误及未知错误继续明确拒绝，不承诺几秒后恢复。含义依据 [高德官方错误码](https://lbs.amap.com/api/webservice/guide/tools/info)。上游错误码仅允许五位数字，其他内容变为 `unknown`；不回传上游 URL 或任意错误文本。MCP 只接受白名单错误，等待时间的布尔值、文本或越界值均丢弃。

等待时间是建议，不保证到期可用。没有自动 HTTP 重试、自动切换传输或自动重放任务。用户可显式再次查询，或在服务端允许时点“按原条件重试”创建关联新任务；原失败记录保留。无真实结果时不生成替代 POI、交通、评论或价格。

## Web 请求收敛

起终点选择器接收工作区中已有的同 ID POI（来自真实搜索或保存记录），打开编辑器时直接展示，避免重复详情查询。缺少匹配详情时继续使用可取消的真实查询；城市变化、选择变化和卸载仍拒绝迟到响应。

这些信息只复用当前内存和合法保存记录，不把地图事实写进浏览器草稿。保存新行程时，后端仍重新核验起终点和实际路线。起终点查询错误显示建议等待时间并保留原选择；任务区域显示同一恢复建议，等待结束不会自行提交。
