# 时间约束失败与调整引导

日期：2026-10-21。本轮在本地实现分日失败诊断与 Web 输入定位，并用真实高德数据完成失败后重新规划；没有上传 GitHub 或操作个人业务库。

## 后端与共享契约

原有最近邻排序、有限地理候选和调度保持不变。当原方案及已评估候选均不满足每日结束时间时，仍返回失败任务，不保存部分行程。`time_constraint_exceeded` 保留不可按原条件重试的语义；修改条件通过原创建/调整接口显式提交新任务。

共享 `Error` 增加可选 `time_constraints`，沿工作进程、任务持久化、HTTP 查询和 SSE 终态传递。OpenAPI 与生成的 TypeScript 类型同步更新，接口路径及请求体不变。历史错误没有该字段时仍可读取，Web 显示通用调整说明。SQLite 沿用 JSON 任务记录，无表结构迁移。

诊断基于本次**原分日方案**已经查询的站间交通，结合该任务的逐站停留设置计算；仅列出超时的日期，不发起额外 Provider 查询。它不是已采用候选，也不是所有候选的最小超出时间。编辑诊断附带原行程 ID，方便界面核对当前编辑来源，仍沿用现有用户隔离。

真实南京样本的错误内容节选：

```json
{
  "code": "time_constraint_exceeded",
  "message": "行程超过每日结束时间；请调整每日时段、站数或停留时长",
  "retryable": false,
  "time_constraints": {
    "operation": "plan",
    "source_itinerary_id": null,
    "basis": "original_partition",
    "day_start": "09:00",
    "day_end": "09:01",
    "available_minutes": 1,
    "days": [{"day_number": 1, "stay_minutes": 60, "travel_minutes": 21, "required_minutes": 81, "overrun_minutes": 80}]
  }
}
```

`operation` 为 `plan` 或 `adjust`。停留分钟取自用户输入，交通分钟取自既有矩阵；缺交通时仍由 Provider 明确失败，不能以零或直线估计补齐。错误不包含 POI 原始返回、凭证、完整路线或部分行程。

## Web 操作

规划过程卡展示原时段、每日可用分钟及各超时日的停留、交通、共需和超出分钟。三个按钮分别定位每日结束、每天站数或当日地点、停留输入；支持原生键盘操作。编辑时自动切换到首个超时日，必要时展开折叠的约束区。

按钮不修改数据或提交任务。用户当前表单可能已变化，诊断始终标明失败任务的原条件；改值不会在前端重新判断路线可行性。用户核对后点击“开始规划”或“保存并重算”，后端重新查询并核验。

编辑失败保留原已保存行程、费用和本机编辑草稿。刷新后诊断随原任务恢复；先恢复编辑草稿，再定位并调整。诊断来源与当前编辑行程不一致时不允许定位到错误的编辑内容。历史错误无分日信息时不生成虚构分钟数。

后端新增 7 项，覆盖原矩阵准确分钟/调用数、逐站时长与编辑来源、所有候选不可行时仅解释原分日、生产 worker 传递结构化错误且无部分结果、历史记录兼容、任务/SSE/重启持久化及禁止原条件重试、编辑失败不改原版本与显式新提交成功。

本轮完整通过 Python 129、共享客户端 23、三引擎页面 141 次，共 199 个逻辑用例、293 次执行；类型/构建通过。最终页面报告无失败、跳过或重试后通过，零重试。真实链路和归档启动单列计数。

浏览器新增两项：规划失败原条件诊断/定位/刷新/显式新任务；第二天编辑失败保留 0 元和停留草稿、刷新恢复、切日与展开定位、保存后新版本正确且原版本不变。完整三引擎结果见 [ACCEPTANCE.md](../ACCEPTANCE.md)。

首轮完整页面回归中，旧概览测试按日期取 API 记录，选中了新增编辑场景产生的调整版本，而页面明确打开原 `SAVED ITINERARY`。证据为页面第 2 天停留 120 分钟、误选的子版本 360 分钟；随后按页面相同条件排除 `parent_id` 的调整版本，原值断言保留，定向三场景通过。原失败 trace/log 保存在本机忽略目录 `artifacts/time-constraints-first-failure/`，未提高超时或启用重试。

## 真实高德 Web 链路

使用独立临时数据库、回环生产 API 和生产 Web 构建，未替换 Provider。浏览器录入南京“公园”、2026-10-22、1 天 2 站、每站 30 分钟、步行；先设置 09:00–09:01，再手动扩大为 09:00–18:00。

- 首个任务真实查询后失败：停留 60、站间交通 21、共需 81、可用 1、超出 80 分钟；行程列表仍为空，没有可按原条件重试的按钮。
- 调整按钮只移动焦点，仍保留 09:01；手动改值后第二次显式提交成功，生成独立新任务，原失败诊断保持不变。
- 成功行程两个 POI 与道路均标记高德来源，道路折线存在；站间 1.552 km、21 分钟。两个任务共 2 次搜索、4 次有向路线查询，上限 6 次，无自动业务重试或模型调用；预算总额仍为未知。
- 页面截图已目视核对。临时服务均优雅退出，库已清理；报告与截图保留在 `artifacts/time-constraints-live/2026-10-21/`，不随 Git 或发布包交付。

重验可在配置自己合法授权的本地 Web 中按上述输入操作，会消耗真实接口配额；数据与路况变化可能得到不同分钟数或明确失败。本轮浏览器 JS 地图配置为空，没有加载真实 SDK；底图和安全密钥代理沿用既有单独验收记录。

时间可行仅覆盖已选地点的用户停留与站间交通，不包含住宿往返、预约、闭馆日或未来时刻实际交通。不能把本次通过解释为出行日保证可行。移动端可读取同一可选错误字段，本轮没有新增 App 或进行真机验收。
