# 每日地理分组与真实交通比较

## 行为

新建多日行程且每天至少两站时，先保留既有推荐排序的分日作为基线，再比较最多三个地理交换候选。所有方案使用同一批推荐 POI，不替换地点、不增加站点、不改变每日站数。单日、每天一站以及显式关闭排序的内部调用保持原行为。

手动编辑仍保留用户的分日，`optimize_order` 仅控制日内排序，不自动跨日移动。编辑生成新版本，不改原行程。旧记录没有 `optimization` 时按 `null` 读取。

## 实现与真实数据边界

1. `services.route_planner.propose_day_group_candidates` 在既有算法模块中复用 Haversine 坐标距离，进行有界、确定性的跨日交换。坐标距离仅用于提出候选，绝不作为真实道路距离、交通耗时或费用返回。
2. `travel.planner` 查询基线与候选的高德有向交通矩阵，继续复用既有最近邻排序及 `_build_route_stops` 时间调度。A→B 与 B→A 分别查询。
3. 同一规划执行内复用已查询的同向路段，基线与候选使用同一份已取得事实比较；无跨请求的供应商数据缓存。总矩阵并集最多 48 个有向路段，默认 MCP 加一次搜索最多 49 次工具调用，低于默认 64 次限额。实际超时、取消和更低的用户配置限额继续生效。
4. 任一必要路线缺失或上游错误均明确失败，不用坐标距离或模型补交通。只在已有真实矩阵的比较中决定保留基线；这不构成模拟数据降级。

当前最多 3 天、每天 4 站，几何交换迭代不超过所选地点数。先选择一个地理候选，再在总路段并集上限内加入不同的邻近交换方案，避免河流、桥梁和道路绕行使单一几何候选误导决策。不穷举全部跨日划分，也不声称全局最优。

## 采用规则

- 基线已满足每日时段：候选须满足时段，且总交通分钟、总道路距离、最忙一天总分钟均不增加，同时至少一项改善，才可采用。
- 基线不满足时段：优先选满足时段的候选；此时距离或交通可能增加，Web 明确显示“原分日超出每日时段”。
- 多个候选符合条件时，依次比较最忙一天总分钟、总交通分钟和总道路距离。
- 所有方案仍不可行时返回 `time_constraint_exceeded`，不保存超时行程。

最忙一天总分钟是从每日开始到最后一站离开的停留与站间交通总和。不包括住宿、出发点往返、预约、闭馆日或未来时刻路况。用户逐站停留、录入费用跟随 POI，不因交换丢失；未知预算仍为未知。

## API 与 Web

`Itinerary.optimization` 是兼容性新增字段，包含策略、采用结果与原因、`baseline`、全部已核验的 `candidates`、最终 `result`、基线每天 POI ID 和实际 `route_queries`。指标包含总距离、总交通分钟、最忙一天总分钟、每日交通分钟和可行性。

OpenAPI 和双端共享 TypeScript 类型已同步。Web 的“分日与交通对比”展示原分日/本次采用的真实指标；没有改善时明确说明保留原分日。手动编辑版本不继续套用旧优化结论。新任务提交时清除旧的完成提示，避免尚在重算时显示上一任务已完成。

## 2026-10-19 本地实测

真实高德样例，均为两天四站、每站 30 分钟、步行、09:00–20:00；直接 Provider 与 MCP 分别调用，结果一致。

| 样例 | 原分日 | 本次采用 | 结论 |
| --- | --- | --- | --- |
| 上海 · 站间交通距离 | 8.030 km | 7.065 km | 减少 0.965 km |
| 上海 · 站间交通分钟 | 108 | 96 | 减少 12 分钟 |
| 上海 · 最忙一天总分钟 | 142 | 123 | 减少 19 分钟 |
| 杭州 · 站间交通距离 | 16.305 km | 16.305 km | 保留原分日 |
| 杭州 · 站间交通分钟 | 218 | 218 | 保留原分日 |

杭州最短地理候选虽然只需 217 分钟总交通，却使最忙一天从 211 分钟增至 260 分钟；其他已比较候选也未满足采用条件，因此保留原方案。上海样例采用一个候选，另一个较差候选被拒绝。两市每次规划各查询 12 个有向路段，加一次 POI 搜索共 13 次工具调用。

结果来自此次查询时的真实返回，仅用于说明样例效果，不代表其他城市或未来出发日的收益。报告、SQLite、截图保存在 Git 排除的 `artifacts/`，凭证留在本地环境文件：

- `live-amap-20261019T095142Z/`：杭州直接 Provider/MCP、调整版本、Web 对比及刷新验证。
- `live-grouping-20261019T095408Z/`：上海直接 Provider/MCP 的最终契约与真实比较报告。
- `live-map-20261019T095529Z/`：上海真实地图、对比卡片、跨天切换与刷新恢复的 12 项浏览器检查及实测截图。地图相关响应无 HTTP 错误，已目视核对底图与路线；未重新查询 POI/路线。

早期实时浏览器检查还暴露了验收脚本的 innerText/textContent 比较不一致及外部字体等待超时；已修正脚本文本检查并屏蔽与业务无关的字体请求，后续完整链路通过。未据此修改地图或供应商数据。

## 回归与后续

新增 13 项算法检查，覆盖有向事实、已有算法复用、道路绕行拒绝、多候选选择、时间约束、最忙一天、费用/停留保留、最大调用上限、手动分日及旧记录兼容。新增一个 Chromium 场景，覆盖对比展示、刷新和手动编辑分日保留；整个无密钥回归集共 108 项。真实联调另记，不使用测试数据作为生产结果。

下一步扩大城市/交通模式样本，评估更大候选集的收益与接口成本，再完善出发/返回位置、营业时间窗。保持同一后端算法层；跨日全局优化、票价与预约须另行设计和授权验收。
