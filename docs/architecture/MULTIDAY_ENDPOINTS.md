# 多日共享出发地与返回地

日期：2026-10-22。沿用现有 Vue3 Web、FastAPI、Provider/MCP、推荐函数、最近邻排序和时间调度；没有第二套 Agent 或业务算法。原 Flutter 保留，本轮不含真机联调。单日阶段记录见 [SINGLE_DAY_ENDPOINTS.md](SINGLE_DAY_ENDPOINTS.md)。

## 使用与数据流

表单支持 1–3 天、每天 1–4 站。可搜索真实 POI，设置每日共用的出发地、返回地，或只设置一侧。起终点不占游览站数。开始时间表示每日离开出发地，结束时间包括抵达返回地；每一天重新从同一开始时间调度。未选择一侧沿用首站/末站时段，不推断住宿、接送或跨夜交通。

Web → 共享生成类型/客户端 → FastAPI 异步任务 → 统一工具层 → 高德 POI/有向路线 → 现有排序、调度 → 持久化行程及事件 → SSE/轮询。编辑保留原分日；默认保留指定顺序，只请求连续站点及实际两侧路线。勾选重新排序时，仍使用真实有向距离矩阵。失败不保存半成品，不覆盖来源版本。

编辑及刷新恢复支持共享起终点，明确清除会应用到所有日期。地图、时间轴、多日概览、版本对照使用已保存路线，展示时不由 LLM 或前端计算交通估计。三天可以使用同一住宿 POI，但没有逐日不同住宿选择、住宿价格、预订或库存能力。

## 契约与兼容

`PlanRequest.day_origin_poi_id` / `day_destination_poi_id` 仍是可空 POI ID，现在表示每日共享地点。省略或 null 表示未选择。`EditRequest` 省略表示保留，显式 null 表示清除；不迁移旧数据，不改变旧请求空字段的幂等指纹。

每个 `Day` 分别保存 `origin_poi`、`destination_poi`、两侧 `Segment`、出发及返回时间。最后游览站的 `travel_to_next` 保持 null；返程单独存储。相邻端点 ID 相同不查询路线，也不制造零分钟路段；不同方向分别查询，缓存仅限同一任务。

`GroupingOptimization.route_queries` 是任务去重后的全部真实路线查询数，包含起终点；新增 `candidate_route_limit` 和 `candidate_search_limited`，旧记录默认 null/false。`tool_budget_limited` 明确表示在额度限制下没有额外分日候选，不等同于没有地理改进空间。对比指标包含停留、站间及所选往返；不保证全局最优。

时间失败继续返回四部分：停留、站间、入站、返程，按受影响日期列出超时。多日预算缺项为往返费用标注日期；未知总额保持 null，不使用人均消费充当票价。

## 64 次工具调用预算

`backend/travel/planning_budget.py` 统一计算 API 调整准入、规划器和质量验收的上界。默认 MCP 上限保持 64，不提高核心依赖或默认配额。

设游览站数 N、天数 D、所选侧数 B、不同共享端点数 A：

- 新规划查 POI/端点上界为 1+A。自动分日的站间候选有向边并集上限为 `min(48, N*(N-1), 64-(1+A)-N*B)`，复用现有有界地理候选函数。两侧路线预留 N*B，不按地理距离编造交通。
- 保留顺序编辑只请求 N-D 个站间边、D*B 个实际往返边；详情按游览及端点 ID 并集去重。
- 重新排序编辑预留各日完整矩阵和 N*B 个边界边。超过 64 时，API 返回 422 `planning_budget_exceeded`，在任务受理和外部查询前拒绝；可保留原顺序、减少站点或清除一侧后重试。不会静默取消重新排序。

| 组合 | 调用边界/离线实测 |
| --- | --- |
| 单日四站双端点新规划 | 23 次，原行为保持 |
| 单日四站双端点重排序编辑 | 26 次 |
| 三天四站双端点新规划 | 保守上界 64；候选站间上限 37，本次用例只查询基线 36，实际总计 63 |
| 三天四站双端点保留顺序编辑 | 最多 29 次，实际 stdio MCP 用例验证 |
| 三天四站双端点重排序编辑 | 保守需求 74，提前拒绝 |

请求缓存可能减少调用，上界不是账单计数。64 次也不保证在 150 秒 MCP 总期限内完成；外部超时、拒绝、取消继续走现有失败路径，不生成替代数据。较小 MCP 配额仍可失败，不自动加额。

真实 Web 通过跨日展示、清除返回地后的草稿刷新、离线提交恢复、保存新版本与来源对照。将原版本每日结束改为 11:05 后，两日分别超出 159、171 分钟，任务失败且原记录不变。独立 MCP 在默认配额下通过同一请求的来源、每日调度、缺失字段和未知预算核验，耗时 27.72 秒。

Web 辅助 POI 读取有一次 429 `tool_busy`、一次 502 `provider_rejected`，选择保留，规划后端随后独立核验成功；没有伪造替代响应。整次运行预算上限 81（Web 58、MCP 23），不是实际账单计数；无自动重试或额外付费重跑。报告和截图在忽略目录 `artifacts/multiday-endpoints-live/2026-10-22/`，密钥和业务记录不进入源码发布包。
