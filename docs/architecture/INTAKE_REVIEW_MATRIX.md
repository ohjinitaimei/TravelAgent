# 需求理解与连续使用验收

日期：2026-10-28。继续本地 Web 优化，保留同一个 HelloAgents、FastAPI 和数据/算法层。本包不上传 GitHub，不增加高德调用或自动模型重试。

## 固定输入与判定

沿用 `scripts/live_requirements_cases.py` 和 `verify_live_clarification.py`，保留 legacy、complete15、partial-daily，增加以下三个固定输入。预先定义期望值，不根据模型回复改答案。

| 场景 | 必须保留的含义 | 不允许的结果 |
| --- | --- | --- |
| relative-date | 参考日的明天；第 1 天只指定开始、第 2 天只指定结束；其余子项为空 | 漏日期、按主机日期计算、把两天各自时段拼成共用时段、填默认停留 |
| ambiguous-constraints | 城市/关键词/两天确定；预算、交通方式和开始时间尚未决定；保留每条歧义原文 | 任取一个预算、模式或开始时间，或者只保留预约而丢掉歧义 |
| explicit-correction | 明确由 1 天/驾车/800 元改为 2 天/步行/600 元 | 继续使用已撤回的值，或将明确修正当作未决定 |

所有成功草案继续检查 15 个字段、连续原文依据、来源、未自动确认、用户确认、0 元预算、明确清空、422 无效合并和 409 旧版本冲突。补充阶段不创建新任务、不调用模型或路线、不生成行程。新增差异列表仅记录已知字段名，避免只看到第一个不符项而遗漏其他错误。

## 实现

- 同一 Agent 的说明明确区分“未决定的多个候选”与“明确改为最终值”。
- 后端从请求的参考日计算今天/明天/后天，作为模型上下文；处理跨年、闰日和日期上界。它不改写草案，不为未表达的日期补值。相对日期证据仍须引用用户原词。
- 针对实测错误补充逐日示例，明确第 1 天开始和第 2 天结束不能成为共用时段。Schema、单次请求、超时和零重试保持原约束。
- 模型超时、连接失败、限流、授权拒绝和请求拒绝使用固定中文提示；保留 `llm_call_failed` 错误码。授权和请求配置错误不标记为可重试。提示不含 SDK 原始消息、响应体、地址或凭据。
- Web “仍需人工处理的要求”提供可访问区域，解释原文与已保存条件的区别。确认字段不代表已验证预约/营业要求，补充后保留原文记录。
- 新增可复用的 `scripts/verify_live_requirements.py`：固定三个场景，每场景至多一次草案请求；新建隔离库，关闭地图凭据，核对任务/事件和零行程，核对源码与配置未变化并正常关闭、清理。报告目录预先保留且拒绝覆盖。

测试回复仅在 `tests/` 中注入，不作为生产降级。没有新增业务数据、推荐算法或核心依赖。

## 复现方法

完成 README 的模型配置和可选依赖安装后，在项目根目录执行。此命令显式调用真实模型，最多三次；不使用个人业务库，不修改环境文件。

```powershell
.\.venv\Scripts\python.exe scripts/verify_live_requirements.py --allow-model-call --reference-date 2026-10-28 --date 2026-10-30 --run-id intake-review-example
```

再次执行须换新 run-id。相对日采用参数给定参考日，适合固定样本复验；人工验收当天的表达时应更新参数。失败不会自动重发。产物在 `artifacts/`，不随源码发布；对外仅分享经过筛选的汇总，避免披露本机配置或模型服务日志。

## 接续的真实行程评价标准

下一包在已有质量检查器中先固定城市、关键词、天数、模式、时段和起终点，并预留外部调用额度。每个场景分别报告：来源/字段完整性、关键词相关性、每天交通占比、最长路段、最忙一天负担、约束满足与基线收益。与基线比较须复用同任务的真实道路事实；无改善保留原方案，缺价格/预约/营业数据继续为空。

人工复核单列“愿不愿意实际采用、理由及需改哪一天”，不从任务成功率或关键词字面命中推导满意度。最终再统一进行完整九套浏览器、HTTPS、恢复、独立归档启动和发布候选核验。移动端、正式服务器和高级多 Agent 仍按后续里程碑推进。
