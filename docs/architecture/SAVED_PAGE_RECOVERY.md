# 分页焦点、状态提示与失败恢复

更新日期：2026-10-21。本阶段在已有全库查询与快照分页上完善 Web 交互，不更改 API、数据库、共享契约、Provider 或业务算法。

## 页面行为

“已保存行程”新增可聚焦的“第 N 页行程”标题。使用上一页、下一页、刷新或读取重试后，请求成功才更新列表、页码和游标；焦点到新结果起点，随后按 Tab 可以进入首张行程卡片。首次进入页面、输入搜索和切换筛选不主动移走当前输入焦点。

| 操作 | 成功时 | 失败时 |
| --- | --- | --- |
| 上一页/下一页 | 保持原查询快照，替换为目标页，定位新结果标题 | 保留原页内容、页码、总数及游标；定位失败摘要 |
| 重试失败的翻页 | 使用相同条件和原目标页游标，不创建任务 | 继续保留原页，等待显式重试 |
| 刷新 | 保留筛选条件，新快照读取成功后显示第一页 | 保留刷新前的页，包括第二页；不先清空旧列表 |
| 搜索或筛选变化 | 清除旧结果，从新查询第一页开始 | 不将旧条件结果显示为新查询成功结果 |
| 离开页面或退出账号 | 取消当前读取、使响应失效 | 迟到内容和焦点操作均不能进入其他页面或账号 |

列表状态使用独立的 `role=status`、`aria-live=polite` 和 `aria-atomic=true`，给出目标页读取中、当前页/匹配数、失败后仍保留哪一页等信息。结果容器标记 `aria-busy`，分页按钮通过 `aria-controls` 关联结果；状态位于忙碌容器外，避免等待期间的提示被一起延后。

错误摘要可聚焦，提供目标页或刷新失败的说明及“重试列表读取”。它不承诺新结果已经显示，也不把网络错误变成空行程或模拟数据。读取期间禁止重复翻页；失败后恢复原页按钮，编辑草稿继续保留。

## 焦点与异步保护

显式动作会记录本次交互序号。等待过程中如果用户继续按键、点击或把焦点移到其他控件，旧请求完成时只更新有效数据，不再移动焦点。搜索输入保持可用，不因较慢的分页响应而丢失输入位置。

请求代次与取消信号继续保护数据归属：条件变化、组件卸载或账号空间关闭，都会使旧读取失效。聚焦前还会等待 Vue 更新，并再次核对请求代次与交互序号；禁用按钮产生的自动 body 失焦不被当作用户已经转移操作。组件卸载时移除事件监听。

新记录插入不会进入旧水位内的前后页；显式刷新才纳入新记录。这一行为沿用原后端游标实现，本轮增加浏览器端的实际插入和刷新验证，没有在前端重复开发分页查询或业务算法。

首个定向用例先在原实现中失败：第二页已有测试服务返回的 15 条记录，但没有可聚焦的新结果起点。核对代码确认列表读取完成只更新数据，不处理焦点；刷新还在发送请求时清空当前页。随后增加结果标题、显式动作焦点保护，并将刷新替换推迟至有效成功响应后。未改变超时或启用重试掩盖失败。

四项工作台场景验证：

1. Enter 翻页和返回后聚焦结果标题，Tab 到首卡；窄屏无横向溢出；状态属性与忙碌标记正确。延迟读取期间移到搜索框，响应到达不抢焦点，继续输入仍可搜索。
2. 浏览器实际离线时，第二页请求失败、第一页的 50 个 ID 保持不变，焦点到失败摘要；联网后显式重试使用相同游标。第二页再遇刷新 503 仍保留相同 15 个 ID，刷新重试成功后才回第一页。费用编辑值 29 保留，列表交互没有业务 POST。
3. 旧第二页响应被延迟时修改条件，新查询只显示匹配版本；释放旧响应后结果、页码和输入焦点不变，没有残留旧错误。
4. 通过隔离测试服务实际创建一条符合查询的新行程，旧快照的第二页、总数及回退第一页 ID 均不变；显式刷新后总数增加一条，新版本出现在第一页。

账号场景在旧账号第二页真实 GET 已完成但响应尚未交付时退出，确认工作区清空；登录另一账号后释放旧响应，只显示新账号第一页的 50 个 ID，不混入旧账号内容或页码。

首次全套执行在既有 WebKit 账号第 12 项的 beforeEach 遇到约 63 分钟系统休眠，30 秒准备超时。Windows 电源事件 42/1 显示上海时间 17:01 进入休眠、18:04 恢复，与测试持续时间一致；其余工作台新增场景此前均已通过。唤醒后不修改代码或时限，重跑 WebKit 账号 13 项，并执行该次未运行的 WebKit 生产构建 5 项；不启用框架重试，不删除中断日志。最终覆盖规模仍按检查集计数，复跑不增加逻辑用例。
