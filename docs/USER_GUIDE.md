# TravelAgent 使用手册

本手册面向 Vue3 Web 工作台，按实际界面说明从启动到保存版本的操作。Web 与后续移动客户端共用 `/api/v1/travel` 后端；当前 `apps/mobile` 是接入说明，原 Flutter 源码保留，不能当作已联调的 uni-app。

## 1. 安装和启动

准备 Python 3.12、Node.js 22.12+ 和 npm，在项目根目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.travel.lock.txt
npm ci
if (-not (Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
```

已有虚拟环境时直接使用它。不要用示例覆盖自己的 `.env`。Linux/macOS 使用 `python3`、`.venv/bin/python`，并仅在目标不存在时复制配置。

在 `backend/.env` 填入自己的 `AMAP_WEB_KEY`，确认具有 POI 搜索和步行/驾车路线权限。默认结构化表单不依赖模型。分别在两个终端运行：

```powershell
# 终端一：项目根目录，单实例、单 worker
.\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```powershell
# 终端二：项目根目录
npm run dev
```

打开 <http://127.0.0.1:5173/>；API 文档在 <http://127.0.0.1:8000/docs>。若后端改用 18000 端口，启动 Web 前设置 `$env:TRAVEL_BACKEND_URL='http://127.0.0.1:18000'`。更换配置后重启对应服务。

| 能力 | 必需配置 | 未配置时的行为 |
| --- | --- | --- |
| 真实地点、路线、生成行程 | 后端 `AMAP_WEB_KEY` | 明确报告查询失败，不生成替代地点或交通 |
| 大屏底图、标记、路线折线 | Web `VITE_AMAP_JS_KEY`；后端匹配的 `AMAP_JS_KEY`、`AMAP_JS_SECURITY_CODE` | 工作台可启动，底图不可用；后端查询仍取决于 Web 服务 Key |
| 自然语言整理草案 | 可选 HelloAgents 依赖、模型配置及开关 | 可直接使用结构化表单 |
| MCP 数据工具 | 可选 MCP 依赖、`TRAVEL_TOOL_TRANSPORT=mcp` | 默认 `direct` 使用同一 Provider 与算法 |

配置 JS 地图时，仅在 `apps/web/.env.local` 设置公开的 JS Key。安全密钥只留在后端，经同源地图代理使用；不要设置 `VITE_AMAP_SECURITY_CODE`。依赖安装和配置详见 [根 README](../README.md)、[地图代理](architecture/AMAP_PROXY.md)、[MCP 接入](architecture/MCP_CLIENT.md)。

默认 `TRAVEL_AUTH_MODE=local` 是共享本地空间。需要个人空间时先创建账号：

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m travel.accounts create alice
Pop-Location
```

密码在终端隐藏输入。设置 `TRAVEL_AUTH_MODE=session` 并重启后端，再从 Web 登录。HTTP 本机使用 `TRAVEL_COOKIE_SECURE=0`，HTTPS 使用 `1`。切换到登录模式不会自动把原本地记录划给新账号；迁移方式见 [账号说明](architecture/AUTH_ISOLATION.md)。公网部署还需执行 [部署检查](architecture/DEPLOYMENT.md)。

## 2. 创建第一份行程

1. 在“行程工作台”填写目的地、地点关键词与出发日期。可先尝试“南京 / 公园 / 1 天 / 每天 2 站”，结果取决于当时真实接口返回，地点名称和交通不作固定承诺。
2. 选择每天站数、每站停留、每日开始和结束时间、步行或驾车。当前上限为 3 天、每天 4 站，每站停留 10–360 分钟。
3. 按需要填写总预算。未填的费用保持未知；设定预算上限不代表系统已经获得真实票价。
4. 点击“开始规划”，在“规划过程”查看任务 ID、执行事件和状态。长任务由后端异步执行，可主动取消；刷新后恢复当前任务，不必再次提交。
5. 看到“行程已生成并保存”后检查时间轴、地点和数据来源。只有任务成功且结果同步后才将新行程显示为当前版本。

自然语言入口用于整理草案：在“用一句话，整理旅行需求”中提交文字，核对“待核对的需求草案”，在“核对与补充字段”中补齐并确认字段，再点击“填入表单并核对”。这一步不会自动规划；人工核对后仍需“开始规划”。“仍需人工处理的要求”不能当作已经满足的约束。草案修订冲突时先记录尚未保存的补充；显式加载最新草案会替换这些输入，再核对并确认。

如果每天时段过短，系统会显示“时间约束调整建议”，列出失败方案的停留、站间交通和超出时间。点击“调整每日时段”“调整每天站数”或“调整停留时间”定位字段。修改后再次点击“开始规划”，创建新的任务；原失败任务和诊断保留，不会改写为成功。

## 3. 查看地图、多日行程和地点

- 用 DAY 按钮切换日期，先查看多日概览中的站数、停留、交通和费用缺项，再检查当天时间轴。
- 地图地点编号与时间轴支持双向选择。底图不可用时仍可读取时间轴及地点列表；底图加载故障不会触发模拟地图数据。
- 点击地点查看详情，读取来源和获取时间。评分、消费、营业时间可能缺失；人均消费不是门票价格，也不自动作为预算。
- “探索地点”使用后端授权搜索。编辑时搜索并新增地点后，保存时会重新核对真实地点和路线。

交通为接口获取时点的站间结果，不是出发当天的保证。当前每日时段不包含从住宿/出发地到首站、末站返回、餐饮或预约等待。未来日期营业、预约资格、真实票价与库存须另行核实。

## 4. 编辑、恢复草稿与保存新版本

1. 打开一个已生成行程，点击“编辑行程”。可调整站点顺序、分日、停留和用户录入费用，或搜索新增/移除地点。
2. 对照“本次编辑改动”及地点预览。编辑中的线路和费用不是重算后的结果；点击“保存并重算”才调用后端。
3. 等待“编辑草稿存储”显示“已保存在本机”。同一浏览器、同一账号的未提交输入可保留 7 天。刷新/重开后点击“恢复编辑草稿”，系统先核对来源版本，再恢复输入；恢复不会自动提交。
4. 点击“保存并重算”。成功会生成关联来源 ID 的调整版本，原版本保留。失败时保留原行程和编辑输入；根据原因修改或恢复连接。
5. 退出编辑或打开其他行程时，按“有未保存的行程修改”提示选择继续编辑或放弃修改。切换工作台页面本身保留当前编辑。

草稿只是本机输入恢复，不是云端备份。浏览器清理存储、隐私模式、存储失败或换设备会影响恢复。看到存储错误时，先保留当前页面与输入，不要把它当作已保存行程。多标签页冲突应按提示显式选择，不能假设后一页会自动覆盖。显式退出登录会清理当前账号的浏览器恢复记录；会话过期后同账号重新登录的恢复行为与主动退出不同。

## 5. 预算与约束、保存列表和版本对照

“预算与约束”分别显示已知费用小计、总预算上限及待补全费用。用户输入 `0` 表示该站费用被明确录为 0；空值表示未知。即使小计为 0，也可能显示“总额未知，无法确认预算满足”。系统不推算门票、酒店或交通收费填空。

在“已保存行程”中，可按标题、城市、出发日期或完整版本 ID 搜索当前账号的全部记录，筛选原行程/调整版本并排序。每页最多 50 条，翻页沿用查询快照；点击刷新才纳入新记录。读取失败时保留原页，按重试继续读取原目标。

调整版本可点击“对比来源版本”，只读比较地点、停留、已保存交通和费用。对照不会重算路线，也不会覆盖当前编辑。可从对照中打开来源或调整版本；“直接调整版本”只计算直接子版本，不包括更深层后代。不同版本交通的获取时间可能不同。

## 6. 故障恢复

| 页面情况 | 操作 | 需要核对的事实 |
| --- | --- | --- |
| 已受理任务，但状态/事件读取中断 | 等待有界重连；出现“恢复连接”后点击 | 继续读取同一任务，不重新规划 |
| “尚未确认任务已受理”，出现“恢复上次提交” | 恢复网络后点击此按钮 | 保留原请求和提交标识；避免手动另发一次 |
| 任务成功但提示结果尚未同步 | 恢复连接，读取同一任务结果 | 原行程暂留，不代表新结果已读取 |
| 时间约束不可行 | 按诊断定位字段，修改后显式提交 | 原失败记录保留，编辑失败不修改来源 |
| 外部查询失败、缺授权、无足够地点 | 检查后端授权/配额或修改关键词 | 不会生成模拟结果填空 |
| 限额拒绝并给出等待时间 | 等待后显式提交 | 自动刷新不会反复重放被拒请求 |
| 来源版本不存在或无权读取 | 保留输入，核对账号或重试 | 不绕过账号隔离，不强行恢复草稿 |
| 退出登录/换号 | 登录目标账号后重新读取 | 旧账号迟到响应不能覆盖新空间 |

“按原条件重试”仅在服务端允许时出现，仍使用原条件。需要改条件时修改表单并创建新任务。排查时提供任务 ID、错误码和操作步骤即可；不要发送密码、Key、Cookie 或 `.env`。

## 7. 复现验收和备份

离线自动验收与真实联调分开。自动验收使用隔离的 TEST ONLY 数据库，不访问用户业务库，也不把测试数据用作生产降级。

```powershell
# 安装可选适配依赖，以便完整检查导入和协议边界
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.helloagents.txt -r backend/requirements.mcp.txt -c backend/requirements.travel.lock.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/verify_repository.py
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.cache/playwright"
npx playwright install --only-shell chromium firefox webkit
.\.venv\Scripts\python.exe scripts/verify_browser.py
```

仅复现生产构建的弱网、最大行程和连续操作流程，运行 `scripts/verify_browser.py --suite resilience`。Linux 首次安装浏览器加 `--with-deps`。新连续场景的步骤、真实数据实测及本轮运行范围见 [完整用户流程验收](architecture/WEB_USER_JOURNEY.md)，历史检查见 [验收记录](ACCEPTANCE.md)。

日常需备份后端 SQLite 业务库；不要把浏览器草稿当备份。已有在线快照、校验和恢复命令，按 [运维说明](architecture/OPERATIONS.md) 与 [发布包/备份说明](architecture/RELEASE_BACKUP.md) 操作，恢复到新路径并验证后再切换。

提交源码不包含 `.env`、安全密钥、SQLite、个人行程、缓存和本机验收 artifacts。当前操作以本地验收和发布包为准；GitHub 上传另行执行。
